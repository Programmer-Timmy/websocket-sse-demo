📚 Wat zijn WebSocket en SSE?

WebSocket en Server-Sent Events (SSE) zijn technologieën voor real-time communicatie tussen een client (bijv. browser) en een server. Beide maken het mogelijk dat de server data naar de client stuurt zonder dat de client telkens een nieuw verzoek hoeft te doen. Ideaal voor chat, live updates, gaming en dashboards.

WebSocket

↔️ BI-DIRECTIONEEL

WebSocket is een bi-directioneel protocol dat een permanente verbinding onderhoudt. Beide partijen kunnen op elk moment data sturen.

Hoe werkt het?

WebSocket begint met een HTTP-handshake waarbij de client de server vraagt de verbinding te upgraden. Als de server akkoord gaat, wordt de verbinding omgezet naar WebSocket.

Vanaf dat moment kunnen beide partijen berichten versturen in tekst of binaire vorm via frames. Elk bericht wordt ingekapseld in een frame, zodat meerdere berichten tegelijk veilig over dezelfde verbinding kunnen lopen. De WebSocket API heeft functies en events zoals send(), onmessage en onclose.

Je kunt verschillende soorten berichten versturen door in de payload een type mee te geven. Bijvoorbeeld:

  • chatMessage - voor chatberichten.
  • lampOn - voor een lamp aan/uit commando.

De client kan op basis van dit type bepalen hoe het bericht verwerkt moet worden.

Het protocol is ontworpen voor snelle, continue en bidirectionele communicatie.

Voorbeeld van een WebSocket-bericht:
{"type":"chatMessage","message":"Hallo, ik ben een WebSocket-bericht!"} *type is optioneel (wel aantraden als je meerdere soorten berichten wilt verwerken)*

Voordelen

  • ✓ Lage latency door permanente verbinding
  • ✓ Beide partijen kunnen berichten sturen
  • ✓ Geen overhead van HTTP headers
  • ✓ Ondersteunt binary data

Use Cases

Chat Apps Multiplayer Games Live Collaboratie Trading Platforms

Server-Sent Events

➡️ UNI-DIRECTIONEEL

SSE is een eenrichtingsverbinding waarbij de server continu updates naar de client kan sturen via een open HTTP-request. De client kan geen data terugsturen via deze verbinding.

Hoe werkt het?

SSE gebruikt een open GET-request. De server stuurt data in een speciaal tekstformaat en de client kan dit verwerken.

Een SSE-bericht kan de volgende velden bevatten:

  • data: - de inhoud van het bericht
  • id: - uniek ID, handig bij reconnect
  • event: - optioneel, type bericht
  • retry: - optioneel, hoe lang wachten voor reconnect

Elk bericht eindigt met een lege regel. Als de verbinding verbroken wordt, probeert de client automatisch opnieuw te verbinden.

Voorbeeld van een SSE-bericht:
data: {"type":"notification","message":"Nieuwe update beschikbaar"}
id: 1
event: update

 *id en event zijn optioneel* **Eindigt met een lege regel**

Voordelen

  • ✓ Eenvoudig te implementeren (gewone HTTP)
  • ✓ Automatische reconnect ingebouwd
  • ✓ Werkt goed door firewalls
  • ✓ Event ID's voor message tracking

Use Cases

News Feeds Live Dashboards Notifications Stock Tickers

Vergelijking

Feature WebSocket Server-Sent Events
Communicatie Bi-directioneel (↔️) Uni-directioneel (➡️)
Protocol WebSocket protocol (ws:// of wss://) HTTP/HTTPS
Reconnectie Zelf implementeren Automatisch
Complexiteit Gemiddeld Simpel
Data Format Text, Binary Text only

Kies WebSocket wanneer:

  • ✓ Je bi-directionele communicatie nodig hebt
  • ✓ Client én server data moeten sturen
  • ✓ Lage latency cruciaal is (gaming, chat)
  • ✓ Je binary data wilt versturen

Kies SSE wanneer:

  • ✓ Alleen server → client updates nodig zijn
  • ✓ Je een simpele oplossing wilt
  • ✓ Automatische reconnectie belangrijk is
  • ✓ Je door firewalls moet (HTTP)

💻 Zelf de Demo Runnen

Wil je de demo lokaal draaien? Volg deze stappen om het project op je eigen machine te installeren.

Prerequisites

  • Node.js (v18 or higher)
  • npm or yarn

Installatie Stappen

1. Clone de repository

git clone https://github.com/Programmer-Timmy/websocket-sse-demo.git
cd websocket-sse-demo

2. Installeer dependencies

npm install

3. Start de backend server (Terminal 1)

npm run server

Server draait op http://localhost:3100

4. Start de frontend (Terminal 2)

npm run dev

Frontend draait op http://localhost:5173

API Endpoints

WebSocket

wss://ws.school.timmygamer.nl

Production endpoint (WebSocket Secure)

ws://localhost:3100

Local development endpoint

HTTP / SSE

  • GET /api/events

    SSE endpoint voor real-time server updates

  • POST /api/broadcast

    Broadcast bericht naar alle WebSocket clients

  • GET /api/health

    Server health check
